# Manual first-time Nextcloud AIO installation – v1.0.0

**Scope:** an existing Nextcloud AIO host, **no pre-existing passwords_otp installation**, Nextcloud 35.0.2, official Passwords 2026.11.20, PostgreSQL, PHP 8.3–8.5 and persistent custom_apps storage.

**No in-place upgrades.** The installer intentionally refuses any existing OTP app and must not be used to replace an earlier pilot version. The existing Passwords app is never changed.

**This is an unsigned public source build**, not an App Store-signed package. The manifest carries production_approved=false because general production support has not been established; the operator must explicitly accept the remaining restrictions. The legacy installer CLI flag --accept-unapproved-rc is still used by 1.0.0 for this acknowledgement.

## 1. Back up and inspect

Verify an actual, restorable Nextcloud AIO/Borg backup including PostgreSQL and the persistent app volume. Keep the passphrase and documented restore procedure available. Choose a real, limited Nextcloud group (example: otp-pilot). Do not select --all-users just because a group is missing.

Build and fully test a **single clean Git commit**, then copy three files from that exact checkout to a private directory on the **AIO host**:

- passwords_otp-1.0.0.zip (generated by scripts/release.py);
- scripts/aio_install.py;
- scripts/release.py.

Never mix installer scripts from different commits or reuse a hash from a different ZIP. On the AIO host use chmod 600 on these files. Run commands from that directory.

~~~sh
sha256sum passwords_otp-1.0.0.zip
sudo python3 aio_install.py --inspect
~~~

Expected: AIO_INSPECT_PASS. Do not proceed if Nextcloud, Passwords, PHP, PostgreSQL, image or persistent app storage differ from the supported combination.

## 2. Verify group and preflight

Replace the example group with the **exact existing group ID**. Replace SHA256_FROM_THIS_PACKAGE with the 64-character hash of the **actual newly built ZIP**.

~~~sh
sudo docker exec -u www-data nextcloud-aio-nextcloud   php /var/www/html/occ group:info 'otp-pilot' --output=json

sudo python3 aio_install.py --preflight   --package ./passwords_otp-1.0.0.zip   --sha256 SHA256_FROM_THIS_PACKAGE   --group 'otp-pilot'
~~~

Expected: AIO_PREFLIGHT_PASS with scope=otp-pilot. The preflight is read-only with respect to Nextcloud application data, but records an installer receipt under /var/lib/passwords-otp-aio-installer/.

The installer checks the exact package, supported versions, app absence, group identity and persistent volume. A missing group is a **STOP**, not a fallback to global access.

## 3. Explicit first install

Only after inspecting the receipts, confirming the backup and accepting the WebUI-token residual risk:

~~~sh
sudo python3 aio_install.py --install   --package ./passwords_otp-1.0.0.zip   --sha256 SHA256_FROM_THIS_PACKAGE   --group 'otp-pilot'   --confirm-production   --ack-aio-backup   --accept-unapproved-rc   --accept-browser-token-risk
~~~

Expected: AIO_INSTALL_PASS: 1.0.0. If the installer prints STOP, **do not retry blindly**; inspect the transaction journal and app registration.

It stages only passwords_otp in the persistent custom_apps volume, validates file hashes, enables that app using occ and immediately checks exact scope. No SQL patches or container restarts are intended.

## 4. Independent verification and browser acceptance

~~~sh
sudo python3 aio_install.py --verify   --package ./passwords_otp-1.0.0.zip   --sha256 SHA256_FROM_THIS_PACKAGE

sudo docker exec -u www-data nextcloud-aio-nextcloud   php /var/www/html/occ config:app:get passwords_otp enabled
~~~

Expected: **AIO_VERIFY_PASS** and a group-scoped JSON value such as ["otp-pilot"], never yes unless --all-users was explicitly requested and approved.

In browsers, verify the app with a member of the pilot group and verify denial for a user outside it. Using synthetic entries, check TOTP display/copy, shared entries, CSE challenge, new record creation, logout in another tab and expiration handling. Never paste credentials or raw network bodies in issues.

## 5. Rollback / emergency disable

The installed ZIP, source commit, installer scripts, checksum and state receipts must be retained. The strict rollback checks that the original AIO fingerprint and package files have not changed:

~~~sh
sudo python3 aio_install.py --rollback   --package ./passwords_otp-1.0.0.zip   --sha256 SHA256_FROM_THIS_PACKAGE   --confirm-production --ack-aio-backup
~~~

After an AIO update, a separate option --allow-aio-update-for-rollback permits **only** an explicitly confirmed emergency disable of the exact previously installed OTP app, after verifying the original install receipt, unchanged own app files, registration and **the same persistent volume**. It does **not** restore the database. Stop and use the independent AIO backup if identity or state is uncertain.

**Caution:** These rollback commands target only an original **1.0.0 install recorded by this installer**; do not use them to manage a previously installed 0.7.3 pilot package.
